# TextBook Swap SA: User Stories and Tasks

**Project:** TextBook Swap SA — Second-Hand Textbook Swap

## 1. Introduction

User stories describe the features and functionality that students need from the TextBook Swap SA platform. They help the development team understand user requirements and divide the work into manageable tasks.

## 2. User Stories and Tasks

### User Story 1: Search for Textbooks

**User Story:** As a CPUT student, I want to search for textbooks by title or author so that I can find the books I need for my modules.

**Tasks:**
- Create the textbook search interface.
- Implement the search functionality.
- Display textbooks matching the search criteria.
- Test the search functionality.

### User Story 2: Filter Textbooks

**User Story:** As a CPUT student, I want to filter textbook listings so that I can find books that meet my requirements.

**Tasks:**
- Design the filtering interface.
- Implement the available filters.
- Display textbooks matching the selected filters.
- Test the filtering functionality.

### User Story 3: List a Textbook

**User Story:** As a student, I want to list a second-hand textbook so that other students can discover and acquire it.

**Tasks:**
- Design the textbook listing form.
- Provide fields for textbook details.
- Display listed textbooks on the platform.
- Test the listing process.

### User Story 4: View Textbook Details

**User Story:** As a student, I want to view a textbook's details so that I can decide whether it meets my academic needs.

**Tasks:**
- Design the textbook details page.
- Display the title, author, module and condition where available.
- Make textbook details easy to read.
- Test the textbook details page.

### User Story 5: View Textbook Condition

**User Story:** As a student, I want to see the condition of a second-hand textbook so that I can make an informed decision before acquiring it.

**Tasks:**
- Display the condition of each textbook.
- Create a consistent way to describe textbook condition.
- Test how condition information appears on the platform.

### User Story 6: Use the Platform on Different Devices

**User Story:** As a student, I want to access TextBook Swap SA on my phone, tablet or computer so that I can find textbooks conveniently.

**Tasks:**
- Create a responsive website layout.
- Test the website on mobile devices.
- Test the website on tablets and computers.
- Fix any layout problems identified during testing.

### User Story 7: Create a Wishlist

**User Story:** As a student, I want to save textbooks to a wishlist so that I can keep track of books I want to acquire.

**Tasks:**
- Design the wishlist interface.
- Implement the ability to add textbooks to the wishlist.
- Display saved textbooks.
- Test the wishlist functionality.

### User Story 8: Access a User Guide

**User Story:** As a student, I want to access a user guide so that I can understand how to use the platform.

**Tasks:**
- Write instructions explaining the platform's features.
- Explain how to search and filter textbooks.
- Explain how to use other available features.
- Review the guide for clarity and accuracy.

### User Story 9: Manage Textbook Listings

**User Story:** As an administrator, I want to manage textbook listings so that the platform's information remains organised and appropriate.

**Tasks:**
- Plan the administrator dashboard.
- Identify the listing management functions required.
- Design the dashboard interface.
- Test the available management functions.

## 4. Reflection

## Reflection: User Stories and Tasks

Working on the User Stories and Tasks for our TextBook Swap SA project helped me understand the importance of identifying user needs before developing a software application. I learned that it is important to consider the system from the user's perspective and understand what students would want to achieve when using the platform.

Our main goal was to create a platform where students could buy, sell and exchange second-hand textbooks at more affordable prices. Developing user stories helped us identify important features and user interactions, such as browsing textbooks, searching for specific books, viewing book details and creating listings.

I also learned how to structure user stories using the format "As a user, I want to..., so that..." This helped us explain the purpose of each feature and the value it would provide. Breaking these stories down into smaller tasks made it easier to understand the work involved, allocate responsibilities and track development progress.

This activity improved my understanding of Agile development because user stories and tasks help connect user requirements with the actual development process. They also allow the team to organise work, prioritise features and make improvements as the project progresses.

Overall, this activity strengthened my requirement analysis and problem-solving skills. It taught me that understanding user needs and planning features properly are important steps in developing a useful and user-friendly application. I will be able to apply these skills in future software development projects.
